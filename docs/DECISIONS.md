# Decisions

Two or three lines per entry: what we chose, why, what it costs.

## 2026-10-17: Host mode, not dedicated servers
Photon Fusion 2 in host mode. One player hosts and is authoritative, bots run on the host. Casual game, so cheating risk is accepted and no server bill. A headless build exists for CI and soak tests only. Cost: host PC load grows with bot count, so bots far from humans run a cheap mode.

## 2026-10-17: Maps from hand-made chunks, not random terrain
The seed only decides which chunks go where. Every piece has been tested by a human, so balance stays testable. Fully random terrain is a possible v2.

## 2026-10-17: Integer math for generation decisions
Clients generate the map independently from the seed, and floating point can differ between CPU architectures. Placement decisions use integers and a custom `SeededRng`. Floats only appear after decisions, for visuals.

## 2026-10-17: In-match upgrades only
No accounts, no saved progression in v1. Avoids a server that stores player data.

## 2026-10-17: AI generated art is reference only
AI output is allowed for reference, mood, and blockout. Nothing AI generated ships as is. Everything is rebuilt and repainted by hand and logged in `docs/ASSETS.md`.


## 2026-10-17: Cinemachine 3 for the camera, direct Input System polling
Cinemachine's third person follow gives the over-the-shoulder camera, wall avoidance and screen shake (impulse) for free. Input is read straight from Keyboard and Mouse into a MechInput struct, with no action asset, so bots can fill the same struct later. Cost: rebinding keys will need real input actions later.

## 2026-10-17: M1 aim rule is a placeholder
Shots go from the muzzle to the point the camera ray hits, starting the ray in front of the camera so it skips our own mech. This is a guess for M1 only. The real rule is still the open question below, due at M3.

## 2026-10-17: Grounded comes from Move's collision flags
`CharacterController.isGrounded` flickered at high frame rates in headless tests, so the mech uses the Below flag returned by Move and sets minMoveDistance to 0.

## 2026-10-17: Gauntlet script as the gate for loops
`scripts/gauntlet.sh` runs every automated check and prints one verdict. A loop only counts an iteration if it passes. It covers tests only, never fun, so playtest gates stay human. New systems add their checks to it (determinism, map validation, import checker, soak) as they land. Cost: it closes nothing by itself, a weak check list gives a weak gauntlet.

## 2026-10-17: Rebuild for the web, server authoritative (supersedes the Unity and host mode entries)
The game must be reachable by link and able to scale, which Unity WebGL and a player-hosted browser tab cannot do well. So: TypeScript and Three.js client, Node server per room that is authoritative and runs the bots. Scale by adding rooms and processes. Cost: a server bill, a rewrite of M1, and no Unity tools. The Unity prototype stays on the `unity-prototype` branch.

## 2026-10-17: Not using Arrr.fun for now
Its ordered tick relay suits lockstep games with a deterministic simulation. Ours is server authoritative with prediction and interest management, and many bots. It is also a young third party dependency. Revisit only if we choose lockstep.

## 2026-10-17: Fixed 60 Hz sim, aim travels inside the input
The mech steps at a fixed 60 Hz and the render blends between steps. Each input carries absolute aim yaw and pitch, so the server can replay exactly what the client did at M2. Look is applied every frame so the camera answers the mouse at once. Cost: shots use the last rendered camera, so there is up to one frame of aim lag on the shot direction.

## 2026-10-17: Plain boxes for M1 collision
World collision is axis aligned boxes with simple step-up for low ledges, shared by client and server. Enough for the grey-box map and cheap to run for many bots. Cost: no slopes, so the old ramp became stairs. Revisit when real chunk art arrives.

## 2026-10-17: Plain `ws` server with our own Room, not Colyseus
Prediction and interest management are custom anyway, and Colyseus's automatic state sync would fight them. The Room class is about 150 lines, has no transport inside it, and is tested without sockets. Cost: no built in matchmaking or room lists, we write those at M5.

## 2026-10-17: Every input is processed once, in order, at most two per tick
The server steps a player once per received input, not once per server tick. That keeps the client's recorded history and the server in lockstep, so replaying after a snapshot reproduces the server exactly (tested to 1e-6 under latency). The two per tick cap lets a lagging client catch up but stops anyone speeding up by sending extra inputs. Cost: a player who stops sending simply freezes.

## 2026-10-17: Shots aim at a point the client sends (M2 stand-in for the open aim rule)
The input carries the world point under the crosshair. The server fires from its own barrel position toward it, rate limited on the player's step clock. So the crosshair stays accurate with our over the shoulder camera, and a client cannot fire faster or from somewhere else. Clients ignore the server echo of their own shots. M3 still decides the real rule and adds hit checks.

## 2026-10-17: JSON messages, everyone sees everyone (for now)
Easy to read while building. Binary packing and nearby only snapshots come at the bandwidth pass (M8) and with bots (M4/M5). Cost: inputs cost roughly 48 kbps upstream, near the 64 kbps budget, so this must be packed before bots and 8 players.

## 2026-10-17: Aim rule: the camera picks the point, the barrel has to be able to reach it
The client sends the world point under the crosshair. The server fires from the barrel toward that point. If a wall is between the barrel and the point, the shot hits the wall. So what the crosshair shows is almost always what you hit, and peeking round corners with the barrel still counts. Settles the open question from M1.

## 2026-10-17: Hitscan with a short rewind, not flying bullets
The server checks a shot instantly against where each target stood about 150 ms ago (data/combat.json), because the shooter was looking at a slightly old picture. The flying bullet on screen is only a fast tracer. Real projectile hits would need lag compensation on every flight frame for little gain at this speed. Cost: the 150 ms is a fixed guess, not each player's measured delay, and the rewind makes it possible to be hit just after running behind cover.

## 2026-10-17: Grenade splash hits every zone, walls block it
A blast damages legs, arms and torso together, scaled by distance, so a close one wrecks parts and makes a story. Includes the thrower. Client and server fly the same deterministic arc, so only the throw and the blast are sent.

## 2026-10-17: Destroyed mechs respawn after 3 seconds (stopgap until M5)
Torso at zero destroys the mech. It looks around but cannot move or fire, then returns at its spawn with full health. This keeps playtests rolling until the real match loop and spectating land at M5.


## 2026-10-17: Double-press W to sprint, Shift to dash
Earlier versions tried tap-Shift, press-Shift and double-press for dashing. Each was fiddly: waiting for release added delay, firing on press made every run start with a dash. Final: two quick presses of W (0.25 s, data/mech.json) start a sprint that lasts while W is held, and Shift dashes at once toward where you are steering, in any of the eight directions, or straight ahead if you are standing still. Holding Shift no longer runs. The dash is a short fixed burst, costs stamina, and has a cooldown, all in data. Both live in the shared movement step, so the server decides them and prediction replays them exactly. Cost: sprinting means releasing and re-pressing W, and a sprint that ran out of stamina carries on by itself once stamina refills if W is still held. Double-tapping A, S or D no longer dashes. Bring that back if you miss it.

## 2026-10-17: Collision grid before generated maps
A 2000 m map has about 12,000 boxes, and every shot, grenade, camera ray and mech step used to test every box. The map now lives in a flat grid of 16 m cells (`World`), and each query only touches the boxes near it. Tested against the old brute force on 2000 random rays. Cost: boxes are only grouped by footprint, so very tall or huge boxes (the ground, the edge wall) sit in many cells.

## 2026-10-17: The map comes from a seed, retries use derived seeds
The server picks a seed and tells clients the seed and tier. Everyone builds the same map from chunk templates in `data/chunks.json`, placed on a grid with integer decisions only and a 32 bit seeded generator (`SeededRng`). If a map fails its checks (blocked spawn, spawns that cannot reach each other, too much sealed off ground), the next attempt uses a seed derived from the first, so every machine ends up on the same map. Tested for 1000 seeds built twice. Cost: chunk numbers must be exact halves and spawnable chunks must keep their middle clear, both checked by tests.

## 2026-10-17: Walkability is a height map with step checks, not a mesh
Each 2 m cell remembers the height of what a mech could stand on. Two neighbours connect when the step between them is within the climb height, so stairs and terraced hills connect, walls do not, and roofs above head height are ignored. The server keeps this grid for bots at M5. Cost: it cannot tell a jets-only rooftop from ground, so those cells just do not count towards "connected ground".

## 2026-10-17: A text scan, not ESLint, guards generation
typescript-eslint does not support our TypeScript 7 yet, so `scripts/check-determinism.ts` scans the generation folder for Math.random, clocks, Date, crypto, engine dependent maths and `**`, with its own tests. Revisit when ESLint catches up; swap it for a real rule then.

## 2026-10-17: Small map spawns sized to the bot target
Small allows 16 spawns, medium 32, large 56, a little over the bot targets in the design (12, 24, 40 players in total including humans). The first guess of 24 on small could not be met on a 6 by 6 chunk map.

## 2026-10-17: Rooms by code, many in one server process
A link like `?room=ABCD` joins that room, and the server makes it if it does not exist. `?create` makes a new room with a fresh code, and the page rewrites its own address to the invite link. A room closes when its last player leaves. A server has a room cap. Scaling is more rooms and more processes, never a bigger room. Cost: room codes are the only access control, which is fine for casual play with friends, and the server does not yet check where a connection comes from.

## 2026-10-17: A match runs lobby, countdown, active, results, and then starts again by itself
The room's host presses Start once. After that every match follows the last with no clicks, which is the "no dead time" rule. If you want to stop, you leave. Each match gets a fresh seed and map, so the next game is never the same arena. Cost: building a map takes up to about 160 ms on the server on the large tier, and the same on every client.

## 2026-10-17: Knocked out means watching, not respawning (replaces the 3 second stopgap)
A mech whose torso hits zero is out for the match. Its player watches a mech that is still standing and clicks to switch. Someone who joins mid match can only watch. Damage, grenades and the ring only do anything while a match is active, so the lobby and countdown are safe to mess around in.

## 2026-10-17: The ring is a schedule, chosen once, damage on every zone
The server picks each stage's circle when the countdown starts and sends the whole schedule. Clients draw the ring from that schedule and the match clock, with no per frame updates. Standing outside takes damage on all three zones every tick, scaled by stage. Circles are chosen so the edge never moves faster than 90% of walk speed, even in the worst case, and a test checks 300 random rings per tier. Numbers are guesses to tune. If the match clock runs out the healthiest survivor wins.

## 2026-10-17: Simple bots now, the full bot system stays at 5b
Pulled forward so there is something to test against: bots run on the server, produce the same input a person's keyboard does, and go through the same movement and combat code. Each one sees whoever is close and in line of sight, aims a few degrees off, holds a comfortable distance and strafes, throws a grenade now and then, heads for the middle of the ring when it is near the edge, and jumps when stuck. They roam and fight in the lobby and between matches too, where nothing does damage, and only freeze for the countdown. One set of numbers in `data/bots.json`, tuned to be beatable. A room gets them from `?create&bots=N` or the menu, up to what the map has spawns for. Left for 5b: easy, normal and hard, path finding round walls, level of detail for far away bots, nearby only snapshots, and filling to a target count as humans join. Cost: they walk straight at things and rely on jets to get unstuck, so they will look dumb around buildings.

## 2026-10-17: The mech body faces where you look, instantly
The body used to swing round at 240 degrees a second to add weight, and it read as lag against the camera. `turnSpeedDegrees` in `data/mech.json` is now 0, which means the body snaps to the aim direction every step, and your own mech is drawn at the camera's exact yaw between steps. Weight still comes from acceleration and deceleration. Set the number above 0 to bring the swing back. Cost: other players' bodies still arrive about 100 ms late, because they are drawn from network snapshots.

## 2026-10-17: Bots come to you between matches, and a first radar
On a Medium map the bots spawned spread across 1000 m and were never in sight, so it looked like there were none. Between matches they now wander within about 70 m of the nearest person and only go for people, not each other. During a match they fight everyone, as before. A small round radar (bottom right) shows mechs within 150 m (`data/hud.json`), bots red, people blue, with you in the middle, forward up, and the ring edge as blue dots. This is the first cut of the 5c radar: it has no noise pulses yet.

## 2026-10-17: Cutting delay without cutting smoothness
Others are drawn on the server's own clock, placed by the tick number on each snapshot, not by when the packet happened to arrive. Their delay is one snapshot interval plus a 15 ms buffer, and it grows only by three times the measured jitter, up to 200 ms. On a clean connection that is about 69 ms where it used to be a fixed 100 ms. Tested against steady jitter: no frame stands still or leaps. Hit checks used to rewind every target by a fixed 150 ms. Now each client reports how far behind its view is (ping plus that delay) with its inputs, and the server rewinds by that, capped by `lagCompensationMs` (250 ms), so a shot lands where it was aimed and a clean connection is not rewound further than it needs. Ping is measured from acknowledged inputs minus the time the server held them. The mouse is locked in raw mode where the browser allows it, so there is no operating system smoothing, and the renderer asks for the high performance graphics chip. Left alone on purpose: the 60 Hz fixed step with blended drawing (up to 16 ms, needed so client and server agree exactly), snapshots at 20 Hz (30 Hz would use half as much bandwidth again, and we are already over the 64 kbps budget until the binary packing at M8), and drawing our own mech slightly ahead (it would clip into walls). Cost: a client can claim any lag up to the cap, which is accepted for a casual game.

## 2026-10-17: Rooms remember their bots, and new rooms get 5 by default while testing
Rooms disappear when the server restarts, and reloading a `?room=CODE` link then quietly made a new empty room with no bots, which looked like bots had vanished. The page address now keeps the room's tier and bot count, and the server gives any new room 5 bots unless the link says `&bots=N` (`DEFAULT_BOTS` changes the default, `&bots=0` means none). The countdown is now 5 seconds (`data/match.json`). Cost: during testing every new room is crowded. Drop `DEFAULT_BOTS` to 0 before real players arrive.

## 2026-10-17: Damage works in the lobby too, with a quick respawn, so bots can be tested
Before, damage only counted in a running match, so shooting a bot in the lobby did nothing and looked broken. Now everything does damage except during the countdown. Outside a match a destroyed mech (a bot or a person) just comes back after 3 seconds with full health, with no knockout, no place, and no effect on the match. In a match nothing changes: out is out. Bots in the lobby shoot at people, so a person standing still will be hit and respawn too. Cost: the lobby is no longer a calm place to wait. Add a safe lobby mode later if friends find it annoying.

## 2026-10-17: Bots fight each other all the time
First I had bots in the lobby ignore each other so they would come to you. You wanted them fighting each other too, so every bot now targets whoever is nearest, person or bot, in every phase. They still wander toward the nearest person when nobody is in sight, so a room does not scatter out of view. Cost: a quiet lobby can turn into a bot brawl a little way off.

## 2026-10-17: Packed binary for snapshots, shots and inputs, and only what is near (pulled forward from M8)
With bots, every client was being sent every mech as readable text: 272 kbps on small, 673 on medium, 1279 on large, against a 64 kbps budget. Snapshots, shots and inputs now travel as packed numbers (`packages/shared/src/wire.ts`, tested round trip and against tampering), and the rare messages (room, results, welcome) stay text. Other mechs are rounded to 10 cm sideways and 5 cm up, and your own state keeps float precision so replaying your movement still lines up. The client rounds its aim to float precision before using it, so both sides run identical numbers. A client is sent only mechs within 250 m (staying in view until 288 m so the edge does not flicker) and only shots, grenades and blasts near it or caused by it. People watching, because they are knocked out or arrived late, get everyone. Cost: messages can no longer be read by eye. The measure script prints sizes instead.

## 2026-10-17: Bots get difficulty, routes, a cheap far mode, and rooms fill themselves
Bots come in easy, normal and hard in `data/bots.json` (50, 35 and 15 percent by default): the harder ones aim closer, wait less before firing, turn faster, see further and dash sideways to dodge. Shots are instant on the server, so there is no leading a target to model. Far goals are walked to along a planned route (A star on a coarse 8 m grid made from the navigation grid, capped at 6000 cells a search, straightened afterwards), and a bot that cannot find a route goes straight, so nothing is ever left without a heading. A bot with no person within 300 m thinks and moves four times a second, never looks for targets, and two such bots that meet fight on paper: the stronger tends to win. A room tops itself up to 12, 24 or 40 players on small, medium and large, counting people, makes room as people arrive in the lobby, and tops up again for each new match. A link with `&bots=N` overrides that. Cost: routes keep to open ground, so bots will not walk up stairs or into buildings, and the coarse grid occasionally closes a pocket a bot could really have left.

## 2026-10-17: Fixed mechs being lifted onto the top of walls
A mech pushed flush against a wall could read as a hair inside it from rounding, and the vertical step then set it on top of the wall. The overlap test now ignores touching within 0.1 mm. A test sends a sprinting mech at 300 walls with awkward numbers.

## 2026-10-17: The soak test plays real matches with pretend browsers
Each soak match fills a room with bots and adds three headless players. A bot brain drives each one, but everything else is what a browser does: it builds the map from the seed, sends packed inputs, reads packed snapshots, predicts and replays. Every tick it checks for bad numbers, mechs off the map, health out of range and the alive count going up. At the end it checks the match finished, places were unique, the 99th percentile tick stayed under 8 ms, nobody was sent over 64 kbps, and prediction never drifted more than 5 cm outside respawns and new maps. Simulated time, so a full 8 minute large match takes about 3 seconds. A random seed each run, printed on failure, and everything random comes from it, so a failure replays exactly. Small runs in the gauntlet on every change, all three nightly in CI. Cost: it uses the room directly, not real sockets. The transport has its own tests.

## 2026-10-17: Knocked out players are sent what is near the mech they watch
They used to get the whole map, which the soak test showed pushed them to over 90 kbps on large. Inputs now carry the id of the mech being watched, and a watcher's snapshots and events are measured from that mech. If it has not said, the nearest mech still standing is used.

## 2026-10-17: The radar points to the zone
When the zone edge is off the radar, or you are outside the zone, an arrow on the rim points to the middle of the zone, and it pulses red while you are outside. While watching, the radar is centred on the mech being watched. Nobody moves during the countdown on the client either now, which stops prediction running ahead and being pulled back as the match starts.

## 2026-10-17: A 200 m Arena tier for quick tests
The three real tiers are too big for quick playtests. Arena is 200 m (4 by 4 chunks), fills to 8 players, and has its own ring timings, and the menu starts on it. It is a testing size, not one of the three tiers in the design. The menu also starts on "Fill with bots" now, so a new room tops up to its tier's size.

## 2026-10-17: Sound on the radar (noise pulled forward from M6)
The radar showed every mech within 150 m through walls, which made hiding pointless. Now it only shows mechs within 40 m without them making a sound (`data/hud.json`), all in one colour so it never gives away who is a bot. Everything else shows only when it makes noise. Each action has a loudness radius in `data/noise.json`: walking is silent so sneaking works, then running (55 m), dashing (70), jets (120), gunfire (220) and grenade blasts (320). Anyone within earshot gets a pulse on the radar a little off the true spot, never the exact one: up to 15% of the distance, at most 25 m. Pulses are orange for gunfire and blasts and white for movement, and sounds beyond the radar's edge show as a mark on the rim. A mech makes at most one pulse of each kind every 0.75 s. Bots hear through the same path and go to look when nobody is in sight, unless that would take them out of the zone. Noises ride inside the snapshot at 5 bytes each, so bandwidth barely moved (32 to 43 kbps in the soak). Left for M6: noise from destroyed props and looting, and noise from repairs at M7.

## 2026-10-17: Props are seeded boxes that switch off when destroyed
Each chunk gets 2 to 5 props (crates, junk piles, red explosive barrels) on a 1 m grid, clear of the chunk's own boxes and of spawn spots, drawn from the seed so every machine agrees. A prop's id is its place in the map's list. Each has hit points on the server and one shared state: whole or gone. When it breaks, its box is switched off in the collision world (no fracturing, and the navigation grid does not change), every player in the room is told (collision has to match for everyone's prediction, and it is only a few bytes), it makes a loud "smash" on the radar, and a barrel blows up a beat later with grenade style splash that also hits other props, so barrels chain. A late joiner gets the list of what is already broken, and each match starts whole on its fresh map. Loot from props is gate 6b. Generation checks prop density stays within bounds (`data/props.json`). The soak test caught that a client must apply destroyed props too, or its prediction walks into walls that are gone.

## 2026-10-17: Placeholder sound built in code, real files plug in by data
There were no sounds at all. Every sound is now made on the spot from noise and tones with Web Audio: gunfire, bullet impacts, blasts, smashing props, the hit marker, getting hurt, dash whoosh, jet hiss while held, heavy footsteps, grenade throws, countdown beeps and go. World sounds come from where they happen, so you can hear which way a fight is. The ears follow the camera. Volumes live in `data/audio.json`, and giving a sound a `file` there plays that recording instead, which is the art hook. At most 24 sounds play at once so a big fight does not turn to mush. M mutes. Browsers only allow sound after a click, so it starts with the click that locks the mouse. Cost: placeholder sounds are thin next to real recordings.

## 2026-10-17: Faster, punchier explosions
Blasts felt slow. The fireball now bursts to full size in under a tenth of a second and fades out, with a quick flash of light. The grenade fuse is 1.5 s (was 2), and a barrel goes off 0.06 s after it breaks (was 0.15), so chains still ripple but snap.

## 2026-10-17: Loot and a two slot loadout, no ammo for guns
Broken crates and junk piles roll loot from `data/loot.json` (barrels drop nothing): grenades, armor plates, and the two new weapons. Every weapon is data in `data/weapons.json`: the Autocannon everyone starts with, the Scattergun (8 pellets, wide spread, short range, each pellet its own hit) and the Spike Driver (slow, heavy, long range). Two slots, 1 and 2 or the mouse wheel, with a quarter second pause after switching. Guns have no ammo: hunting for bullets is a rule, not a story, so weapons differ by how they fire instead. Grenades are now a count (start with 1, carry up to 4) with a short gap between throws. Armor comes as plates per zone that soak damage before hit points and show bolted on the mech, so you can see who is protected and where, and a plate vanishes the moment it is used up. Grenades and plates are collected by walking over them, only when they are any use. A weapon needs E within 3.5 m: it fills an empty slot, otherwise it swaps with the one in hand and drops that at your feet. The server checks range and rate. A weapon switch only happens when the client asks for a different slot than last time, so the server can put a new weapon in hand itself without an input already in flight switching it back. Each new match starts everyone on the starting loadout with a clear floor. Cost: the nearby pickups ride in every snapshot, which raised bandwidth to about 50 kbps in the soak. Sending them only when they change would win that back if it gets tight.


## 2026-10-17: Looting a wreck is E held for 2 seconds, and spills everything on the floor
A knocked-out mech's wreck stays where it fell. Holding E within reach of one fills a bar for 2 s (`wreckLootSeconds` in `data/loot.json`), rattles, and pulses a "loot" sound on the radar (90 m, between a dash and jets), so looting is a gamble: you stand still and everyone near knows. Letting go or stepping out of reach starts it again from nothing. When it fills, the wreck throws every weapon, each grenade and a plate for each armored zone on the ground in a ring round it, and its plates come off so it looks emptied. Then the normal pickup rules apply (walk over small things, E for weapons). Spilling, not straight into your loadout, keeps one rule for picking things up and lets a third mech run in and steal the spill, which is a better story. A press of E still takes a weapon first; only holding near a wreck loots. A wreck is looted once.

## 2026-10-17: Bots loot when nobody is in sight
With no one to fight, a bot goes for the nearest thing within 40 m it would actually take (a grenade it has room for, a plate for a zone without one, a weapon when it has an empty slot) or a full wreck, walks onto it and holds E. Loot beats chasing a noise but never the ring. Bots only take weapons into an empty slot, so a bot can end up with a Scattergun and the wrong fighting distance, which is funny rather than a problem. The room picks the goal a few times a second, not every tick. Numbers in `data/bots.json` under `loot`.

## 2026-10-17: Map validation checks loot props, overall and near every spawn
Props marked `dropsLoot` in `data/props.json` (crates and junk, which `loot.json` must agree with, checked on load) are counted: between 300 and 2200 per square km over the map, and at least 2 within 50 m of every spawn, so nobody starts in a desert. At 30 m too many spawns came up short (measured over 40 seeds per tier); at 50 m a bare spawn is rare and a retry with the next derived seed fixes it. Distances are compared squared in whole metres, so the decision is exact on every machine.

## 2026-10-17: Broken parts change how you play: crawl on broken legs, wild aim with broken arms
Each zone reads intact, damaged (under half its hit points, `damagedBelowFraction` in `data/zones.json`) or broken (zero). Broken legs make the mech crawl: 40% of walk speed, no sprint, no dash, but the jets still work, so a legless mech can still hop out of trouble. It lives in the shared movement step as a `crawling` flag the server sets from leg hit points and sends in your own state, so prediction steps it the same way. The one thing prediction cannot know is the moment the legs break: it learns that from the same snapshot, so that moment gets one small correction (the soak test skips judging it, as it does for respawns). Broken arms still fire, with three times the spread (`brokenArmsSpreadMultiplier`), and cannot throw grenades. Wild aim was chosen over "cannot shoot" because a mech that can still fight badly is funnier than one that can only run. Grey-box look: a damaged part sparks now and then and smokes lightly, a broken one smokes black, broken legs drop the body onto two stubs and tip it forward, the HUD bars go yellow then red. Numbers and art hooks in `data/damageFx.json`. A new match or a lobby respawn mends everything.

## 2026-10-17: Pickups are sent only when the list near you changes
Every pickup within range rode in every snapshot, and with wreck spills a medium match reached 65 kbps per player, over the 64 budget. Pickups lie still, so the server now remembers which ones it last sent each client and sends the list again only when it changes. Otherwise one byte says "unchanged". Snapshots arrive in order over the WebSocket, so the client just keeps the last list. The same seed now measures 51 kbps.

## 2026-10-17: Repair is F held, standing still, back to running order
Holding F fixes the part with the smallest share of hit points left, as long as it is under 40% (`repairToFraction` in `data/zones.json`). It takes 6 s (`repairSeconds`) and brings the part back to 40%: legs walk again, arms aim again, but you are not new, so hiding to heal up fully is not worth it. Moving, firing, jetting, dashing, throwing, letting go or taking any damage at all (including on armor) starts it over. It makes a "repair" pulse on the radar (80 m) and throws welding sparks everyone can see, so stopping to repair is a gamble, which is the story. One part per hold: a mech with two bad parts holds F twice. Bots with a part under the line repair whenever nobody is in sight and the ring is not pushing them, and fight instead the moment someone shows up. They do not look for cover first: out of sight is the cover. Repair speed is a single number, ready for an upgrade in M8.

## 2026-10-17: Four upgrades, two sockets, taken with E
Upgrades are found in the match only, as a rare drop from crates and junk (`upgrade` in the drop tables of `data/loot.json`) and in what a looted wreck spills. Four, each one big change, all in `data/upgrades.json`: Big Tanks (60% more jet fuel), Quick Hands (repair and loot twice as fast), Big Ears (hear sounds from 60% further, radar shows twice as far), Overclock (25% faster fire rate on every gun). A mech has two sockets. E takes one like a weapon: an empty socket first, otherwise the one fitted first comes off and drops at your feet, so carrying two is a choice. A second of the same is refused. Each upgrade bolts a grey-box part on the mech in its colour (tank on the back, toolbox on the hip, antenna, coil on the gun), so you can see what someone carries, and the HUD lists them. Bots go for one when they have a free socket. The fuel tank size is part of the mech's own state (`fuelScale`) so prediction steps it the same as the server. Item numbers: upgrades start at 64, so weapons can grow up to 60 kinds without a clash. Cost: two more bytes per mech in each snapshot, about 2 to 4 kbps.

## 2026-10-17: Live tuning goes through the server, behind DEV_TUNING
The tuning panel used to change numbers only in your own browser. Online that does nothing to the server, which decides movement and damage, and it makes your prediction disagree with it. Now every gameplay number in the panel is a change to one number in a data file (`mech`, `weapons`, `grenade`, `zones`, `loot`, `upgrades`, `bots`, `noise`, `combat`), sent to the server. The server sets it in its copy of the raw file, parses the file again with the same checks as loading (a bad value is refused and nothing changes), copies the result into the live values in place (so bots and everything else already holding them see it), and sends the change to everyone in the room, the sender too. Each room tunes its own copy, so one playtest never changes another room, and someone joining later is sent the changes so far. The server only listens when started with `DEV_TUNING=1`; without it the gameplay sliders are switched off online. Offline practice applies changes at once. Map files are not tunable, since the map is already built. "Copy <file>.json" on each file puts its current values on the clipboard in the file's own shape, so a balance change is pasted into `data/` as a data change. The camera stays yours alone.

## 2026-10-17: Medium rooms fill to 28, small and large stay
Measured with `scripts/measure-bots.ts` over many seeds (numbers in PERF.md). ## 2026-10-17: The V1 look: Three.js toon material, box outlines, palette by name
One master material (`toonMaterial.ts`), Three.js's toon material with the light in three flat bands from `data/look.json`, plus a hard warm rim where a surface turns from the camera, so shapes separate from what is behind them. The ground gets the bands without the rim, because a rim on a big flat floor draws a hard line across it. Outlines are a slightly bigger copy of each box drawn from the inside, in the base colour darkened (never black). That is the cheapest outline that stays clean on boxes (pushing faces out along their normals splits the corners), and it is a fixed width in metres, so it thins with distance as DESIGN.md asks. Colours are named from DESIGN.md's palette in `data/palette.json`; the map's old hex colours are remapped onto it, so the generation data does not change. Accents are guesses to judge: blue for you, bone white for everyone else, both clear of moss and rust; barrels in spark yellow so explosive things read as hazards. Lighting is one warm key, a cool sky and soot ground fill, and warm grey fog. The style page is its own entry (`style.html`), so the game is untouched until V1b.


## 2026-10-17: One route search per room per tick, and no searches into sealed pockets
Profiling the large tier under the load test showed the slow ticks were bot route searches, not garbage collection (collector pauses were about 0.2 ms): 6 to 11 searches of 1 to 2 ms each landing on the same tick. On the 2000 m map the 8 m search grid is 250 by 250 cells and about 40% blocked, so one search looks at 2000 cells on average, and a goal in one of the map's 500-odd sealed pockets used up the full 6000-cell cap every time. Now each room runs at most `searchesPerTick` searches per tick (`data/bots.json`, 1); a bot that misses out keeps its old route and asks again next tick, which nobody can see. A failed search waits for the next replan instead of trying again every tick. The pathfinder labels which open cells can reach each other once per map, and a goal in a pocket the bot cannot reach is swapped for the nearest cell it can, so the route ends right outside instead of searching the whole map first.

## 2026-10-17: The look across the game, and an asset checker without a dependency
Every map box, prop, mech, pickup and the ring now use the V1 look. The map and props are drawn as one instanced mesh per colour plus one for its outlines; the floor gets the bands with no rim and no outline. Your mech has the blue accent, everyone else bone white. The zone ring is magenta, the only magenta in the world as DESIGN.md asks, at a lower opacity than the old blue, because magenta tints the whole view much harder. Shared toon materials are no longer thrown away between matches, only the meshes. Cost on large: triangles and draw calls about double, work per frame 0.5 to 1.0 ms, still 60 fps in the browser pane; the laptop reading is still to come. The asset checker (`scripts/check-assets.ts`, in the gauntlet) reads `.glb` and `.gltf` files itself, since the JSON part of a model is all it needs, so no new dependency. It fails a model with a bad name or a missing state (`Mech_..._Intact`, `Prop_..._Destroyed`), over its triangle budget, or with any material but MasterToon; a prop under 300 triangles is only noted. Rules in `data/assetRules.json`; the chunk budget of 20000 is a guess.

## 2026-10-18: Aim at the mech under the crosshair, and a hit marker for every hit
Shooting at an arm did nothing. The arm took damage fine; the shot never reached it. The crosshair's aim point only looked at the map, so with a mech in front of a far wall (or the sky) the aim point was far behind it, and the shot, which leaves from the barrel beside and below the camera, crossed the mech a metre or so off the crosshair: wide of a half-metre arm, still on the torso. The client now also checks the ray against other mechs' hit zones where they are drawn, so the aim point is on the part you are pointing at. The server still decides the hit. Every hit that lands now pops four tick marks round the crosshair (red and bigger on a knockout) and shows what it struck and for how much under it ("ARMS -12", "SPLASH -40", "LEGS BROKEN" when a part already at zero takes nothing).

## 2026-10-18: The mech kit format, proven with a stand-in before any art
A mech is a kit of parts (`data/mechKits.json`): torso, jets, sensor, two legs, two arms, each belonging to one hit zone (legs, arms, torso). Each part is one `.glb` per damage state, named `Mech_<Kit>_<Part>_<State>.glb` (Intact, Damaged, Broken), modelled in place in the mech's own frame (feet at 0, forward is -Z) so nothing needs placing in code. Each file holds three levels of detail as nodes LOD0, LOD1, LOD2 (switched at 25 and 80 m), an empty node `Fx` where that part's sparks and smoke start, and on the gun arm `Mount_Gun` where the gun goes. The game swaps a zone's parts to its state as hit points fall, so a broken leg is the art's own stub, not a shrunk box; the crawl pose, damage tint, plates, upgrades and effects work unchanged. Outlines on real models push each vertex out along its normal (boxes split slightly at the corners, smooth-shaded art does not). The asset checker now also demands LOD0 to LOD2 in every mech part and counts only LOD0 against the 10k budget. A missing file makes the whole kit fall back to the grey-box mech, never half a robot. The stand-in kit is boxes written as real `.glb` files by a script (no new dependency), so the pipeline is tested against actual files. Kits are off by default (`?kit=standin` to try) until a real mech exists. Models are served from the repo's `assets/` folder.
